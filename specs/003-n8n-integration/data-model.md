# Data Model: n8n Workflow Automation Integration

**Date**: 2026-08-04 | **Branch**: `003-n8n-integration`

---

## Overview

This feature introduces two categories of entities:

1. **n8n-native entities** — managed entirely inside the n8n instance; the Next.js app never
   reads or writes them directly (they are accessed via the MCP server)
2. **App-side entities** — TypeScript interfaces that live in `lib/types/n8n.ts` and describe
   the data the Next.js app produces and logs

---

## n8n-Native Entities

### Workflow

An automation sequence defined and stored in n8n.

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID) | n8n-assigned; immutable |
| `name` | string | Human-readable label; unique per instance |
| `active` | boolean | `true` = production webhook live; `false` = deactivated |
| `createdAt` | ISO 8601 timestamp | Set on creation |
| `updatedAt` | ISO 8601 timestamp | Set on any modification |
| `nodes` | array | List of node definitions (trigger, logic, output) |
| `connections` | object | Edge map linking node outputs to node inputs |

**State transitions**:
```
Created (inactive) → Activated → Deactivated → Deleted
```
- A workflow must be **activated** for its production webhook URL to accept requests
- Deleting an activated workflow automatically deactivates it first

**Uniqueness**: Identified by `id`; `name` should be unique per instance but n8n does not
enforce this as a hard constraint.

---

### Execution

A single run of a workflow, recorded by n8n.

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID) | n8n-assigned; immutable |
| `workflowId` | string (UUID) | Foreign key to Workflow |
| `status` | enum | `running` \| `success` \| `error` \| `waiting` \| `canceled` |
| `startedAt` | ISO 8601 timestamp | When the execution began |
| `finishedAt` | ISO 8601 timestamp \| null | null if still running or crashed |
| `data` | object | Per-node input/output data; inspectable in n8n UI |
| `error` | object \| null | Present when `status = error`; contains message and node reference |

**Retention**: n8n retains execution history per its configured pruning setting (default:
last 100 executions per workflow). No custom retention configuration is required for this
feature.

## App-Side Entities

These types live in `lib/types/n8n.ts` in the Next.js app.

### WebhookPayload

The JSON body the app POSTs to an n8n webhook URL.

```typescript
interface WebhookPayload {
  query: string;        // the user's car search message text
  messageCount: number; // total messages in the conversation at trigger time
  timestamp: string;    // ISO 8601 UTC timestamp of the trigger
}
```

**Validation rules**:
- `query` must be a non-empty string (trimmed); empty strings are not posted
- `messageCount` must be a non-negative integer
- `timestamp` is generated by the app; not supplied by the client

---

### TriggerLogEntry

A structured entry appended to `n8n-trigger.log` when a webhook call fails.

```typescript
interface TriggerLogEntry {
  timestamp: string;    // ISO 8601 UTC
  webhookUrl: string;   // the URL that was called (masked to path only in logs — no secret exposure risk, but good practice)
  payload: WebhookPayload;
  error: string;        // error.message from the caught exception
}
```

**Log format**: One JSON object per line (newline-delimited JSON / NDJSON), appended via
`fs/promises.appendFile`. This allows `tail` and line-by-line parsing without loading the
full file.

**Retention**: No automatic rotation. The file is local to the developer's machine and
is excluded from version control via `.gitignore`. Manual deletion is the expected
maintenance action.

## Entity Relationships

```
n8n instance
  └── Workflow [1] ──── [*] Execution

Next.js app
  └── WebhookPayload ──HTTP POST──▶ Workflow (via webhook URL)
                              failure
  └── TriggerLogEntry ──append──▶ n8n-trigger.log
```

The Next.js app has a one-directional relationship with n8n:
- **Write**: fires webhook POST → n8n creates an Execution
- **Read**: developer reads Execution history via Claude (MCP tools), not via the app

The app never reads Workflow or Execution data directly.
