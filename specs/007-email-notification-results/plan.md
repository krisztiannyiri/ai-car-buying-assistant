# Implementation Plan: Email Notification for Car Search Results

**Branch**: `007-email-notification-results` | **Date**: 2026-08-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/007-email-notification-results/spec.md`

## Summary

When the car search workflow returns one or more matched listings and the request includes a valid `userEmail`, a formatted HTML email summarising the matched cars is dispatched to that address. The email step is non-blocking — a delivery failure or missing/malformed address records a warning and the workflow completes successfully. A new `userEmail` field is added to the webhook payload, captured from the user via a pre-chat UI input in the Next.js app.

## Technical Context

**Language/Version**: n8n Workflow SDK (JavaScript ES2020 in Code nodes); TypeScript 5.x for Next.js source files

**Primary Dependencies**:
- n8n built-in nodes: IF, Code, Send Email (SMTP, `n8n-nodes-base.emailSend` v2.1), No Operation, Set
- SMTP credential (must be created in n8n before deployment; see [quickstart.md](quickstart.md))
- Anthropic SDK (existing; no change)

**Storage**: n8n Data Table `car_listings` (ID: `mj0YdKHUlNanTFsA`) — existing, no schema changes required

**Testing**: Manual verification only (per Constitution Principle V — no automated testing)

**Target Platform**: n8n instance (localhost:5678) + Next.js App Router (localhost:3000)

**Project Type**: Workflow automation extension + minor Next.js UI/API update

**Performance Goals**: Email dispatched within 30 seconds of search completing (SC-003)

**Constraints**:
- Email failure is non-blocking (workflow must complete successfully regardless)
- Absent, null, or malformed `userEmail` → skip email + non-blocking warning
- Price formatted in EUR: `€X,XXX` (comma as thousands separator)
- HTML email: table-based layout, XHTML 1.0 Transitional DOCTYPE, all styles inline

**Scale/Scope**: One email per search execution; single recipient per request
