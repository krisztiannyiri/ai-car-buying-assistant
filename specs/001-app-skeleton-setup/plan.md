# Implementation Plan: App Skeleton Setup

**Branch**: `001-app-skeleton-setup` | **Date**: 2026-08-04 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-app-skeleton-setup/spec.md`

## Summary

Bootstrap a Next.js 16 / React 19 App Router project from scratch. The deliverable is two pages — a Home page containing a structural chat interface placeholder and a 404 error page — wrapped in a shared Layout Shell (header + global styles). No AI integration, no backend, no auth. The visual identity (colour palette, typography, spacing scale) is established here as CSS custom properties in `globals.css` and inherited by all future features.

## Technical Context

**Language/Version**: TypeScript (mandated by constitution — all source files `.ts`/`.tsx`, no `any` types)

**Primary Dependencies**:
- `next@16.3.0` — App Router, React Server Components, built-in CSS Modules, `not-found.tsx` convention
- `react@19.2.8` + `react-dom@19.2.8`
- `typescript`, `@types/node`, `@types/react`, `@types/react-dom` — dev dependencies

**Styling**: CSS Modules + CSS custom properties (zero additional deps; built into Next.js; see research.md §CSS Strategy)

**Storage**: N/A — no data persistence in skeleton

**Testing**: None (Constitution Principle V — no test frameworks permitted)

**Target Platform**: Web browser — Chrome, Firefox, Safari, Edge (latest 2 major versions each)

**Project Type**: Next.js web application (App Router, React Server Components)

**Performance Goals**: Home page fully renders in under 2 seconds on standard broadband (SC-001)

**Constraints**: No horizontal overflow at 320–1280px+; touch/click targets ≥44×44px; no `any` TypeScript types; no Pages Router APIs; no commented-out code blocks

**Scale/Scope**: 2 routes (`/` and catch-all 404), ~4 components, skeleton only — no business logic
