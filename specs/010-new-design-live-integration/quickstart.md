# Quickstart Validation Guide: New Design Live Integration

**Branch**: `010-new-design-live-integration` | **Date**: 2026-08-12

---

## Prerequisites

- Node.js installed; `npm install` completed (including new packages — see below)
- `.env.local` at project root with:
  - `ANTHROPIC_API_KEY` — valid Anthropic API key
  - `N8N_WEBHOOK_CAR_SEARCH_URL` — running n8n webhook endpoint (or a mock endpoint for
    offline testing; search-failure scenarios can be tested without it)
- Dev server running: `npm run dev` → `http://localhost:3000`

### New packages to install before testing

```bash
npm install framer-motion lucide-react tailwindcss @tailwindcss/postcss
```

And create `postcss.config.js` at the project root:
```js
module.exports = { plugins: { "@tailwindcss/postcss": {} } };
```

## Scenario 1 — Complete wizard → real search results (P1)

**Validates**: FR-002, FR-010, FR-011, SC-001

1. Open `http://localhost:3000`.
2. Confirm the new Cora wizard is rendered (dark green sidebar, five steps).
3. Step 1 — select at least one driving option. Confirm the "Continue" button enables.
4. Step 2 — select at least one priority. Click "Continue".
5. Step 3 — adjust the budget slider. Click "Continue".
6. Step 4 — select seats/parking/powertrain. Click "Find my matches".
7. **Expected**: App advances immediately to step 5 with a loading indicator (skeleton cards
   or spinner).
8. **Expected**: After the search completes, real car cards appear — each with make, model,
   year, price (or "Not available"), and a "View listing" link where `sourceUrl` is set.
9. **Expected**: No static `Hyundai IONIQ 5` / `Toyota RAV4 Hybrid` / `Kia Sportage Hybrid`
   placeholder cards remain.

## Scenario 2 — Chat panel: real AI streaming (P2)

**Validates**: FR-001, FR-003, SC-002

1. At any wizard step, click "Ask Cora" (mobile header) or view the right-hand chat panel
   (desktop).
2. Confirm the initial assistant message is present: "I will handle the car jargon…"
3. Type a question (e.g. "What's the difference between hybrid and plug-in hybrid?") and press
   Enter or click Send.
4. **Expected**: Typing indicator (three animated dots) appears immediately.
5. **Expected**: Text streams in incrementally — not all at once after a pause.
6. **Expected**: The response is generated by the AI, not a hardcoded keyword match.
7. Confirm no second submission is possible while streaming (Send button and input disabled).

---

## Scenario 3 — Step-5 chat: AI response references wizard context (P1 + P2)

**Validates**: FR-010, D-001 (research decision — wizard answers in system prompt)

1. Complete the wizard with specific answers (e.g. select "Family life" + "Safety tech",
   electric powertrain, 6+ seats).
2. On step 5 after results load, open the chat panel.
3. **Expected**: Cora's opening recommendation references the user's specific choices (e.g.
   mentions family use, safety, or electric powertrain) rather than asking what you're looking
   for from scratch.
4. Ask "Why did you pick these?" in the chat panel.
5. **Expected**: The response reflects the wizard answers (not a generic "based on your needs").

## Scenario 4 — Zero results (edge case)

**Validates**: US1 acceptance scenario 2

1. Complete the wizard with a very restrictive budget (e.g. $250/mo, $15k total price) and
   Electric powertrain.
2. **Expected**: Step 5 shows a "no matching cars found" message, not an empty card list.

---

## Scenario 5 — Search failure + retry (P1)

**Validates**: FR-006, US1 acceptance scenario 3, SC-003

1. Set `N8N_WEBHOOK_CAR_SEARCH_URL` to a URL that returns a non-200 status (e.g. use a local
   mock or temporarily set an invalid URL).
2. Complete the wizard and click "Find my matches".
3. **Expected**: An error message appears with a "Try again" button.
4. Restore the correct webhook URL and click "Try again".
5. **Expected**: The retry triggers a fresh search and results load on success.

---

## Scenario 6 — Email capture → overflow message (P3)

**Validates**: FR-005, US3 acceptance scenarios

1. Open the chat panel and enter an email address in the email input field.
2. Complete the wizard.
3. If the search returns more than 5 results:
   - **Expected**: The results area shows "X more results — check your email for the full list".
4. If no email was entered:
   - **Expected**: The overflow message appears without the email reference.

---

## Scenario 7 — Reset (P4)

**Validates**: FR-008, US4 acceptance scenarios, SC-004

1. Advance to step 5 with results.
2. Click "New car search" (sidebar or mobile menu).
3. **Expected**: App returns to step 1 with all wizard answers cleared, chat history cleared,
   and results cleared.
4. To test in-flight cancellation: start a search, immediately click "Start over" in the
   header while the loading state is active.
5. **Expected**: No network requests complete after the reset; the app is on step 1.

## Scenario 8 — Old components absent (migration close)

**Validates**: FR-007, D-007 (research decision — deletion sequence)

1. After all above scenarios pass, confirm the following files are deleted:
   - `components/ChatInterface/ChatInterface.tsx`
   - `components/ChatInterface/ChatInterface.module.css`
   - `components/ChatInterface/SearchResultMessage.tsx`
   - `components/Header/Header.tsx`

   `components/newdesign.css`.
3. Run `npm run build` — **Expected**: zero TypeScript errors, zero missing-module errors.

## Passing criteria summary

| Scenario | Pass condition |
|---|---|
| 1 — Full wizard | Real cards on step 5 after loading state |
| 2 — Chat streaming | Incremental AI text, no hardcoded replies |
| 3 — Context in chat | AI references wizard selections on step 5 |
| 4 — Zero results | No-match message shown |
| 5 — Retry | Error + retry button; retry succeeds |
| 6 — Email | Overflow message includes email when set |
| 7 — Reset | All state cleared; in-flight request cancelled |
| 8 — Migration close | No old files; `npm run build` clean |
